# HarmonyOS

ArkTS / ArkUI + ArkWeb 原生外壳，复用电脑网关的 `web/` 页面和 `mobile/shared/web/` 脚本。最低 API 14；具体编译 SDK、目标 API 和版本由本目录的工程配置及 GitHub Actions 固定。

## 使用

底部保留 Codex、Keeper、Magpie、Muse 四个入口，CPA 放在 Codex 的更多菜单；不显示独立 Chat 或 Chat 设置入口。底栏全宽 56 vp，进入已识别的 Codey 聊天后隐藏；网页内不再重复添加一套底栏。首次打开一台电脑或管理站点才创建它的 Web 实例；之后仅切换可见性，不替换 URL、销毁实例或自动刷新。已打开页面的滚动位置、表单和运行中页面状态会保留。主动点击“刷新”、更改站点地址、移除电脑、系统回收进程或应用重启会重新加载或卸载相应页面；内存页面状态不会跨进程保留。

- **Codex**：在电脑网关展开“扫码登录”，使用 ScanKit 系统扫码界面或粘贴完整地址，核对网关后连接。配对码仍由网页通过 `/api/pair` 兑换 HttpOnly Cookie；外壳不另建认证流程。已连接时右上 **•••** 可直接切换已保存电脑；打开过的电脑回到各自原页面和草稿，新电脑才首次加载。重命名不重建网页；移除会卸载该电脑网页并沿用原 Cookie 清除行为。切换不会停止电脑上的模型任务，也不会重放发送或审批等写操作。最多同时保留 100 台已打开电脑；达到上限时先在电脑列表移除一台，已有电脑仍可切换。
- **Keeper**：预置 `https://libo.siasunagv.cn/keeper/`。保留尾斜杠，避免站点无斜杠入口的 HTTP 降级重定向。鸿蒙端保留原生 Keeper 标题栏，右侧用返回、登录、更多三枚图标提供网页返回、登录信息和页面选项。网页内仅保留当前分区、平台摘要与原额度/凭据列表；网页 KEEPER 标题、页面工具栏、平台横条及认证文件工具区收进右上更多菜单。
- **CPA**：首次点击后在应用内填写真实 HTTPS 管理地址，不预设未知服务器地址。
- **Magpie**：预置无密钥基址 `https://libo.siasunagv.cn/magpie/`，地址可配置。内部原导航完整保留，包括会话、各管理页及动态注册的“对话”插件。兼容旧顶栏与新版 `side-nav` 的设置入口；只隐藏由原生刷新、设置等价接管的原控件，不整块隐藏网页顶栏、侧栏或网关选择。未知结构保留原 UI。若服务返回 401 并要求启动链接，在“登录信息”选择“私密入口链接”，仅在本机输入启动服务时提供的完整 HTTPS 链接。

- **Muse**：预置 `https://muse.ai/`，在原独立 Chat 的可见位置提供常驻网页入口；使用现有网页返回、登录信息与更多菜单，不注入 Chat/Magpie 脚本或代为登录。若页面空白，可在 **••• → 用系统浏览器打开 Muse** 主动打开已配置的公开地址；不转交当前页面的查询参数、片段或登录数据。主框架网络／HTTP 错误和被拦截的自动外站跳转会在标题栏下提示，但不能据此判断所有白屏原因。`#weblink` 是允许的同源片段变化，不会触发外壳重新加载。手写 M 图标按官网默认 favicon 重绘为本地 SVG，未选中深灰、选中蓝色。站点及凭据独立保存，不读取或迁移旧 Chat 记录。

历史独立 Chat 的 Preferences、Cookie、登录信息和对话数据不删除、不清空，也不自动迁移到 Magpie 或 Muse；Muse 使用独立站点和凭据 ID。

新增 Codex 连接可直接填写裸局域网主机或 `localhost`，默认使用 `http://主机:18787`，也可显式填写其他端口。完整 HTTP/HTTPS URL、显式端口和已保存连接不改写；裸公网域名继续使用 HTTPS 默认端口，便于自管公开代理。Keeper、CPA、Magpie 和电脑 Python 网关的监听端口不变。

电脑网关同时启用 Codex、DSH 或 Claude 时，在聊天列表顶部的应用名称旁切换；不再叠加网关的底部应用托盘。选择器调用网关当前的原按钮，保留会话切换和已选应用记录；网关轮询重绘后会自动同步。账号管理、第三方通知、应用管理和电脑切换收进右上原生菜单，主页面底部只保留 App 入口。网页原按钮仅隐藏，菜单仍调用原处理逻辑。所有显示适配在 App 中完成，无需修改或更新电脑网关；仅注入 Harmony 主框架，原网页及 Android/iOS 不受影响。旧网关缺少可识别的按钮或标题时保留原导航。

连接 **Codey 远程页面**时，原工具收进现有右上 **•••**：**查看归档会话**同步原筛选的勾选状态，**Codey 控制台**与**退出此设备**分别调用原网页入口，不新增 API，也不停止电脑服务。Cindy 主导的新前端通过 `data-codey-ui="2"`、`data-codey-scene` 和显式 chrome/action 标记接管，不依赖标题、文案或 RNWeb 自动样式类；原生确认后才隐藏 footer，并给 header 右侧预留 64 px。`create` 与 `conversation` 隐藏原生底栏，`list` 和只读控制台显示；控制台返回调用专用原按钮，展开时禁用原生归档/控制台动作，保留设备退出。已发布旧前端没有显式 schema 时仍使用旧识别与紧凑 grid，让“本地电脑 · 已配对”与 Codex 标题同排；已配对仍是认证状态，不表示执行进程在线。未知版本、无效 scene 或缺失/重复控件撤回接管，不猜测或回落旧 schema。这里只改变可见性，不销毁 Web、刷新 URL 或重建输入区；更多菜单仍可切换其他站点或电脑，原生未确认时保留网页自身导航。合同及验证边界见[DOM v2 决定](../../.agents/notes/implemented/architecture/2026-11-13-harmony-codey-ui-dom-v2.md)。

第三方管理页各自有独立 Web 控制器，不加载 Codex 原生脚本或桥接接口，不复制 Codex Cookie。Cookie 遵循域名和 Path，localStorage 按来源隔离；同一域名下服务的 Cookie 是否共享也受服务端 Path 设置影响。非当前站点的顶层外链需用户操作和确认后在浏览器打开，不能自动降级到 HTTP。

Keeper 的 **•••** 提供二级菜单：**页面切换**（原分区导航、数据刷新及当前页面筛选）、**平台筛选**（当前动态平台及数量）、**认证文件**（仅启用、限额/健康、巡检、更新限额）、**站点工具**（原 CPA、语言、主题和更多操作）。网页返回、登录信息、刷新页面及站点设置也在同一菜单；系统返回先关闭本适配层的二级面板。原控件保持在 React 原位置，操作只在用户点击后转交原事件，不自动巡检、更新限额或启停凭据；不新增 Keeper API、凭据桥接或服务器改动。页面排版沿用站点明暗主题、保留原凭据操作，将列表卡片、字号和触控空间适配窄屏。“切换原网页工具栏”可临时显示原布局；已部署页面的结构不匹配时保留无法识别的原控件。

Keeper、CPA、Magpie、Muse 共用 56 vp 原生标题栏，站名单行显示。Keeper、CPA、Muse 保留返回、登录与更多；Magpie 常驻刷新、设置与更多，返回和登录信息收进更多。每枚图标 24 vp，按钮保留 44 × 44 vp 点击区和原生按压反馈，常态背景透明。普通网页返回调用当前页面的浏览历史。保存设置时禁用该站点的保存、取消与输入控件，仍可切换其他页签；旧保存完成不会关闭后来打开的设置。外链确认仅展示来源与路径，查询参数和片段不会显示在原生弹窗中。Keeper 显示适配仅对其固定 HTTPS `/keeper` 路径主框架生效，同源 CPA、Magpie 页面也不注入此适配。

## 记住登录和登录信息

网页登录后的 Cookie 与 localStorage 交由 ArkWeb 持久化；页面加载完成和应用进入后台时主动保存 Cookie。服务端设置过期、退出登录、撤销可信设备、清除应用数据仍可能要求重新登录。Codex 不将会话 Cookie 备份到 Preferences，首版也不包含 Android Keystore 对应的 Codex 凭据恢复和入口自动迁移。

点击 Keeper、CPA、Muse 标题栏的登录信息图标，或通过 Keeper、Magpie 更多菜单选择“登录信息”后，由用户明确保存：

1. 选择“密码/管理密钥”，填写可选用户名和密码/管理密钥，点击“安全保存”。之后点“填入已保存”，应用仅填入当前主框架中唯一可见的密码框，派发输入事件，由用户确认登录。多个密码框或来源/路径不符时拒绝填入。
2. 选择“私密入口链接”，在本机粘贴完整的带密钥链接并安全保存。之后只有点击“打开安全入口”才加载该链接。链接必须属于该站点的 HTTPS 来源和配置路径；普通站点设置不接受含查询参数或片段的地址。
3. 需要时点击“忘记该站点登录信息”。即使更改了站点地址或旧记录损坏，该入口仍可删除此站点在本机的旧登录记录。切换站点、离开登录信息面板或页面导航会清除面板中的临时明文。

保存的数据使用 HUKS 密钥加密，由 `CredentialVault` 绑定站点 ID 和 HTTPS 路径范围；加密或解密失败会报错，不退回明文存储。不自动抓取网页密码，不将密码写入 URL、普通 Preferences、JS localStorage 或日志；私密入口本身作为用户明确授权的导航 URL，仅在使用时交给网页组件。

## 文件与通知

- 上传前核对当前电脑实例、网关、导航代次、完整页面 URL 和顶层真实用户动作。切换电脑会使旧的文件选择结果失效；相机返回允许应用曾临时进入后台，但仍须匹配实例、代次、完整 URL 与 Codex 页签。明确要求拍照且接受 JPEG 的网页输入调用系统相机；照片和普通文件仍各自使用原系统文件选择器，保留从任意可选位置选图的能力。系统相机的后置镜头为默认值，拍照和确认均由用户控制；App 不申请相机或整个照片库权限。预览页不会获得上传或原生 prompt 权限。
- 拍摄结果暂存于应用私有缓存，不自动保存至系统照片库。取消、失败或页面身份变化时删除未交付的缓存；已经交给网页的照片保留到下次进程启动后的首次初始化，以免网页异步读取时文件消失。其他下载缓存和用户文件不受此清理影响。Codey 远程页面的图片与文件合计仍限 **4 MiB**，拍出的照片过大时网页会提示；本应用不自动压缩或放宽限制。
- 原生附件下载仅接受当前网关的白名单附件端点。通过同源网页 `fetch(credentials: 'same-origin', redirect: 'error')` 请求，不把 Cookie 交给会自动跟随重定向的原生 HTTP 栈。默认单个附件上限 **200 MB**（按 `MB × 1024 × 1024` 字节计算）；在 **Codex 原生菜单 → 下载设置** 可输入 **1–4096 MB 的整数**，也可恢复默认。设置只保存在本机，取消或关闭面板不保存，保存失败会保留原值并提示。新值用于下一次下载；正在下载和等待保存的文件继续使用各自启动时的上限，设置本身不刷新网页。切换电脑会取消旧电脑当前的原生附件下载及待保存缓存，不影响其网页草稿或远端模型任务；已发起的系统保存保留源缓存直至结束，迟到失败会标明原电脑。
- 响应长度检查、逐块流读取及保存前复核均使用本次下载的上限；超限提示改用浏览器或电脑。电脑网关自己的附件上限仍然生效，本机设置不能覆盖它；旧网关可能仍是 20 MB，需要用户在电脑网关已有设置中另行调整，本次不修改服务端。保存前再次核对完整缓存，才打开系统保存选择器；已有内容的目标会被拒绝，请换名保存。复制失败不会删除用户所选目标，并提示可能有不完整文件，下载缓存保留供重试；取消下载或下次启动仅清理本应用的临时附件。
- 任务通知需要在 Codex 菜单开启并授予系统通知权限，同时在电脑网关开启“手机 App 通知收件箱”。仅当前已连接电脑、Codex 页签可见且应用在前台时巡检；首次读取、切回页签、恢复前台仅建立游标，不批量弹出历史提醒。发布成功后才确认通知游标；点击通知可返回已保存电脑的对应聊天。无后台保活或厂商云推送。

## 构建

底栏外观：长按底栏，或在 Codex 原生菜单选择“底栏外观”。可实时调节模糊并点“完成”保存；关闭面板保留原设置。API26 且设备支持时可改用系统沉浸材质的五档厚度，其他设备使用 0–100% 的兼容模糊。原生页面与站点顶栏使用暖白底色，电脑卡片以细描边分层，三栏保留蓝色选中态。底栏仍处于独立保留区域，未覆盖网页按钮；已确认的 Codey 会话暂时隐藏这一区域。材质不保证模糊或折射 ArkWeb 网页文字。App 图标为 D，桌面名称 Codex+。

从仓库根目录运行；不要提交生成的 rawfile 副本、SDK、安装包、签名或凭据。

```sh
python -B scripts/build-mobile-harmony.py --prepare-only
node --test tests/host-environment.test.cjs mobile/tests/*.test.cjs
```

`--prepare-only` 仅复制 Harmony 专用的 `branding/app-1024.png` 图标和三个共享脚本，不代表 ArkTS 编译。脚本名与注入顺序固定为 `mobile-ui.js`、`mobile-clipboard.js`、`mobile-system-bars.js`。导航 SVG 直接使用已提交的原生资源，不从 iOS 覆写。

安装工程要求的 HarmonyOS CLI 工具，设置 `HOS_SDK_HOME`，将 `ohpm`、`hvigorw` 加入 PATH 后：

```sh
python -B scripts/build-mobile-harmony.py
```

构建脚本安装工程依赖、调用 Hvigor，并验证 HAP 中存在非空的 `ets/modules.abc`、模块与资源索引、正确应用身份和三个原样共享脚本。输出在 `dist/mobile-harmony/`，附带 SHA-256 和工具链/提交信息。

GitHub Actions 的 **HarmonyOS unsigned HAP** 工作流支持手动执行，并在指定鸿蒙分支相关文件更新后执行。成功后下载 `mobile-HarmonyOS-unsigned` artifact。CI 编译成功与真机操作验证是两种不同证据。

每次交付 HAP 更新都递增 `versionName` 和 `versionCode`，同步根包、Harmony 包清单、“关于”和 UA 中的版本；保留应用身份与签名，不用旧版本号标记新包。

## 安装和验证范围

Actions 默认生成 **未签名 HAP**。安装到真实设备前，需要在自己的 HarmonyOS 开发环境中配置开发者签名与设备授权；应用签名、私钥和设备资料不提交仓库。保持同一应用身份和签名，才可按系统规则升级保留数据。

UA 包含真实 `BridgeMobile/2.1.2-HarmonyOS` 标记及旧网关兼容标记 `BridgeMobile/2.1.2-Android`。新网关优先识别 HarmonyOS，现成旧网关仍可沿用移动端绑定流程。UA 只用于宿主兼容提示；配对、Cookie、CSRF 与原生来源校验仍然适用。

本分支网关只将已有服务器可信标记的有限期设备会话迁移为长期可信。普通浏览器或缺少该标记的旧会话保持原有效期与正常续期规则，不会因请求 UA 改变而成为永久可信；到期后重新登录或扫码配对。

Node 自检直接执行生产 ArkTS 函数、组件方法和生成的页面脚本，覆盖共用 URL 夹具、网关/中继/令牌边界、重定向与下载失败、下载上限输入/持久化/失败回退与任务快照、保存时目标保护、设置保存竞态、忘记凭据的面板隔离、浏览历史返回、外链确认脱敏、通知游标和登录填表边界。拍照分流、过期导航、回调及缓存生命周期也有模拟回归；相机、文件选择器和文件系统由模拟适配器提供。HAP 编译状态以对应提交的 Actions 结果为准；原生 ScanKit、HUKS、系统相机和文件选择器、拍照结果交给 ArkWeb 的真实读取、通知点击、软键盘/安全区、多 Web 实例呈现，以及 200 MB / 4 GB 大附件的真实吞吐、存储空间和超时仍需真机验证，未有捕获的实机画面前不视为视觉验证通过。
